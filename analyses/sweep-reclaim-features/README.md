# Sweep+Reclaim Features (Option 4)

Data-mining pipeline for NQ scalp setups. Records every sweep+reclaim event with ~15 features at the reclaim bar plus outcomes measured over the next 10 bars (5 min). Run for a week, then `analyze.mjs` discovers which feature combinations produce edge at various 1:1 box geometries.

## Why this exists

We built [NQ Sweep+Reclaim Scalp v1.2](../../indicators/nq-sweep-reclaim-scalp/) directly from intuition + the magnet retest data. Empirical result over 82 fills: **41.5% combined win rate, 30% NY-only**. Negative expectancy at 1:1 box.

Two conclusions:
1. The sweep+reclaim *mechanism* still produces tradable events at high frequency — the detection works.
2. The *unconditional* outcome doesn't have edge. Some subset of these events likely does — we just don't know which subset without measuring.

This pipeline collects the data so we can find that subset empirically, the same way [plus15-entry-features](../plus15-entry-features/) discovered which features predicted +15 first-hit bias.

## Files

| Path | Purpose |
|---|---|
| `pine/sweep_logger.pine` | TV indicator. Apply to NQ1! 30s. Emits machine-readable `EVT\|...` labels at each event's horizon. |
| `merge.mjs` | Parses labels into `data/master_<sym>.csv`, dedupes by `(sym, t, side)`. |
| `analyze.mjs` | Conditional analysis. Bins events by each feature, reports win% at multiple box geometries vs base rate. Writes `FINDINGS.md`. |
| `data/master_<sym>.csv` | Growing dataset. Source of truth for analysis. |
| `FINDINGS.md` | Latest analysis report (regenerated by `analyze.mjs`). |

## The event schema

Each `EVT|...` label captures one sweep+reclaim event with these fields:

| Field | Meaning |
|---|---|
| `t` | Reclaim bar timestamp (ET) |
| `sym` | Symbol (e.g. NQ1!) |
| `bkt` | 15m reference candle clock-time as HHMM |
| `sess` | Session classifier (NY / London / Asia / Globex / Other) |
| `side` | `L` (low swept, fade long) or `S` (high swept, fade short) |
| `refR` | Reference candle range (pts) |
| `swDep` | How far past ref the sweep went (pts) |
| `swLag` | Bars from sweep to reclaim |
| `clLoc` | Where reclaim close sits within ref range (0=low, 1=high) |
| `vwapD` | Signed VWAP distance at reclaim (pts) |
| `reg` | Above (A) or below (B) 15m 200MA |
| `htf` | EMA20 vs EMA50 on 15m: Up / Down / Flat |
| `pdhD` | Distance from reclaim close to prior-day high (pts, signed) |
| `pdlD` | Distance from reclaim close to prior-day low (pts, signed) |
| `volZ` | Volume z-score at reclaim bar |
| `prevCol` | Prior 15m candle color: G/R/D |
| `prevRng` | Prior 15m candle range (pts) |
| **Outcomes (measured over `hor` bars after reclaim, default 10 = 5 min):** |
| `mfe` | Max favorable excursion (pts) |
| `mae` | Max adverse excursion (pts) |
| `tt6` | Bars-to-reach +6pt favorable (0 if not hit before stop) |
| `tt10` | Bars-to-reach +10pt favorable |
| `tt15` | Bars-to-reach +15pt favorable |
| `st8` | Bars-to-reach +8pt adverse (0 if not hit; >0 = bar number) |
| `hor` | Horizon used (bars) |

The `tt*` and `st8` fields let us compute win rate at any box where target ≤ 15 and stop = 8 *without re-running the Pine*. To evaluate other stop sizes we'd need to re-run with adjusted Pine logic.

## Daily collection workflow

For NQ:

1. In TradingView, NQ1! 30s, with "Sweep+Reclaim Event Logger" applied.
2. Pull labels via MCP:
   ```
   data_get_pine_labels with study_filter="Sweep+Reclaim Event Logger"
   ```
3. Pipe into merger:
   ```sh
   pbpaste | node analyses/sweep-reclaim-features/merge.mjs nq
   ```
4. Merger reports `+N new rows`. Daily cadence keeps overlap large enough to not lose data even with a missed day.
5. After 3-7 days of collection, regenerate findings:
   ```sh
   node analyses/sweep-reclaim-features/analyze.mjs nq
   ```

## TradingView buffer caveat

TV caps 30s history at ~1.3 days. The logger uses labels (not table) and labels survive longer than 30s bars in display, but the underlying event detection requires bar data. **Read labels at least every 30 hours** to avoid losing events that rolled off the chart.

`max_labels_count=500` limits to 500 visible events. At typical event rates of ~30-50/day on NQ, that's ~10-15 days of buffer.

## When to stop collecting and analyze

- **Minimum sample**: 100 events. Per-feature bins of n≥20 start being readable.
- **Comfortable sample**: 300+ events. Per-feature bins of n≥50 are reliable.
- **Strong conclusion**: 500+ events with consistent lifts across multiple sub-features.

## What we're looking for in FINDINGS.md

The analyzer iterates 5 box geometries (6/8, 10/8, 12/10, 15/8, 15/10) and for each one, bins events by ~10 features (session, side, sweep depth, reclaim lag, ref range, regime, HTF EMA, VWAP side, volume z, prior color).

**Edge candidates** are bins with:
- Lift ≥ +8pp over base rate
- n ≥ 20 events
- Logical consistency across related bins (e.g. if "shallow sweep + above MA + high volume" all individually lift, the combination probably stacks)

**Sobering findings** are equally important: if no single feature lifts win rate above 55% at any box geometry, the sweep+reclaim signal genuinely has no edge in 30s NQ and we should move to a completely different setup type.

## After findings: design v2

Once we have an evidence-backed feature set, we'd build [nq-sweep-reclaim-scalp v2](../../indicators/nq-sweep-reclaim-scalp/) gating entries on the proven feature combinations and using whichever box geometry showed strongest lift. The decision is data-led, not parameter-tuned.
